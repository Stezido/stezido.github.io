Data & privacy

Privacy policy

This policy describes the current personal-use Hausbot application and this public information website.

Last updated: 7 November 2026

1. Operator and purpose

Hausbot is operated by Stezido for a personal property search in Austria. Its purpose is to read property information from the operator’s Gmail mailbox, filter listings by configured locations, keep processing records and deliver relevant information to configured Telegram destinations. There is no public signup or service for third-party mailboxes.

2. Google account access

The application requests Google’s https://www.googleapis.com/auth/gmail.readonly OAuth scope. This permission can read the connected mailbox, including message contents and metadata. Hausbot uses Gmail profile information, message identifiers, message history and raw message contents, and registers or renews a Gmail mailbox notification watch.

Initial or recovery scans apply a configured search for property-alert senders. Incremental processing follows Inbox history and may retrieve other Inbox messages before checking their contents for supported property links. The application is therefore not limited at the permission or retrieval level to reading only property-alert email.

Hausbot does not use Gmail access to send email, delete messages or change their read/unread status.

3. Data processed and stored

The private application database can contain:

  • Listing titles, source links, available property facts, location, price, living area and email-derived descriptions or snippets.
  • Source and Gmail message identifiers, the connected mailbox address, processed-message records, history cursors and watch expiry.
  • Review requests, processing and notification status, timestamps and historical application records.
  • Telegram chat, message, user and update identifiers, and text submitted through the supported review-command flow.

The pipeline does not store complete raw email files as its intended database record. It does store extracted information and descriptions derived from email contents; this can include message text. OAuth credentials are kept separately from this website and, in the cloud deployment, in Google Secret Manager.

4. How data is used and shared

Gmail-derived information is used to provide the property-alert and review workflow. Location-approved listing summaries are sent to the configured Telegram review chat. A recognized save command can forward a listing to the configured results channel. People with access to those Telegram destinations can see the information shared there.

The current application uses Google services for Gmail, authorization, messaging and Cloud Run hosting; Supabase-hosted PostgreSQL for application storage; and Telegram for alert delivery and review commands. GitHub Pages hosts this separate public information website. These providers process data under their respective terms and privacy policies. Operational logs may contain processing status and errors.

The current processing flow does not use AI assessment, and does not automatically fetch property listing pages. Gmail-derived data is not sold, used for advertising or used by Hausbot to train generalized AI models.

Use and transfer of Google API information is limited to this workflow and must comply with the Google API Services User Data Policy, including its Limited Use requirements.

5. Retention and deletion

Application records remain in the private database until the operator deletes them. No automatic expiry or fixed deletion period is currently configured. Copies of messages delivered to Telegram have their own retention and must be removed there separately. Provider logs and backups may follow the providers’ own retention arrangements.

Revoking Gmail access stops future authorized Gmail access; it does not automatically remove information already stored in the application database or Telegram. The operator can request and carry out manual deletion of application records and Telegram copies.

6. Your controls

The connected account owner can revoke Hausbot’s access through Google Account third-party connections. For questions or deletion requests, contact the maintainer through this site’s GitHub issue tracker. Keep any public request free of private message contents and credentials; deletion can be coordinated privately.

7. This information website

This static site has no application login, form submission, advertising or added analytics/tracking scripts. It does not receive Gmail OAuth credentials. GitHub may process visitor IP addresses and technical request information when serving GitHub Pages; see the GitHub privacy statement.

8. Changes

This policy will be updated if the application’s data use changes. The date above identifies the latest published version.
